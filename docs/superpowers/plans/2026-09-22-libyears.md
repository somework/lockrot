# Libyears Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One aggregate number per report — libyears behind, summed over the analysed lock — carried per finding and as a derived block, in JSON, the table, markdown and the HTML page.

**Architecture:** A value object `Lockrot\Analyzer\Libyears` owns the per-package rule (`behind()`) and the fold over findings (`fromFindings()`). `Finding` carries its own `libyears` (nullable float) set in `Analyzer::buildFinding()`; `Report::libyears()` derives the block from its findings, so no constructor changes and every number in the block is checkable against `findings`.

**Tech Stack:** PHP ^7.4 || ^8.0 (no `str_starts_with`, no union types, no `match`), PHPUnit 9/10/11, PHPStan 2, php-cs-fixer, node's own test runner for `resources/report/lib.js`.

**Spec:** `docs/superpowers/specs/2026-09-22-libyears-design.md`

## Global Constraints

- PHP floor 7.4: typed properties yes; union types, `match`, `str_*` 8.0 helpers no.
- No network calls, no new dependencies.
- Years = seconds / 31557600 (365.25 days), the constant `Clock::SECONDS_PER_YEAR` (made public).
- Per-package value stored unrounded on the finding; every printed number rounds once: two decimals in JSON, one in text.
- Exclusion order for a null value: `not_from_composer_repository`, `metadata_unavailable`, `branch_snapshots`, `no_stable_release_date`.
- The schema number stays 1: fields are added, none removed or renamed.
- `summaryLine()` is not touched (the `github` format pins itself against it).
- Conventional commits, imperative subject, in the repository's prose style.
- Gates before the PR: `composer cs`, `composer stan`, `composer test`, `node --test tests/js`, `infection` filtered to the new class.
